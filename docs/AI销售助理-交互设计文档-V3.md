# AI 销售助理 · 交互设计文档 V3
> **定位**：这是《功能设计文档 V2.2》的交互层配套文档。V2.2 定义「做什么」，本文定义「用起来是什么感觉」。
> **日期**：2026-08-28
> **背景**：V12 原型被用户判定「模仿了传统 CRM 的常规界面，丢失了 AI 智能性与助理温度，三栏架构消失，待办逻辑错误」。本文在联网调研（AI-native CRM / Agentic CRM / 情感化设计 / 智能提醒）基础上重做交互设计，产出后再动 HTML。

## 〇、V12 问题诊断（逐条认领）

| # | 用户反馈 | V12 实际做法 | 根因 |
|---|---------|-------------|------|
| 1 | 像传统 CRM，不像 AI 产品 | KPI 大数字卡片 + 图表 + 列表，AI 只是按钮 | 把「AI」做成了功能入口，没做成「在场的工作伙伴」 |
| 2 | 没有助理的温度 | 无问候、无语气、冷冰冰的标签页 | 丢弃了 V2.2 中栏「AI 小助理 · 温暖支持」的定位 |
| 3 | 待办要先看数字再点击跳转 | KPI 卡「待办 5」→ 滚动到列表 | 把待办当成了统计指标，而不是工作本身 |
| 4 | 「3 天未跟进」逻辑错误 | 机械按天数提醒 | 低意向客户 3 天不跟进是正常的；提醒应有**前提条件** |
| 5 | 「先演练再沟通」待办错误 | 高意向客户一律建议先演练 | 把可选工具变成了强制流程；销售把握度高时演练是打扰 |
| 6 | 客户池只有 4 个客户，找不到其他人 | 无搜索、无筛选 | 遗漏 V2.2 §3.1「搜索实时过滤 + 组合筛选 + 自定义排序」 |
| 7 | 三栏架构消失 | 改成了上下堆叠的仪表盘 | 丢失「左待办 / 中 AI / 右数据」同屏一览的核心优势 |
| 8 | 点击后看不到完成动作所需的信息 | 待办点击只跳到客户页 | 待办卡片没有自带「为什么 + 上下文 + 一键动作」 |

## 一、设计北极星：AI 原生 ≠ 传统 CRM + AI 按钮

调研结论（Attio / Salesforce Agentforce / 纷享销客 Agentic CRM / NN/g 2025 AI UX 研究）共同指向一个分水岭：

| 维度 | 传统 CRM（含 V12） | AI 原生销售助理（V3 目标） |
|------|------------------|--------------------------|
| 系统角色 | 记录系统：等人来填、等人来查 | **行动系统**：主动发现工作、备好草稿、等人拍板 |
| 谁找事 | 人找事（翻列表、想该干嘛） | **事找人**（AI 识别出该做的事，连同上下文送到眼前） |
| 数据录入 | 手动填表单 | 说/贴一段话 → AI 结构化 → 人确认 |
| 界面气质 | 表格、字段、菜单 | 对话感、在场感、有名字的助理 |
| 信息密度 | 一屏一个功能 | 一屏三层：要做的事 / AI 的帮助 / 我的数据 |

**两条设计支柱**（用户原话）：
1. **智能性**：AI 自动识别所需工作 → 便捷提醒 → 部分事务自动执行以提效。
2. **温度**：一眼看出这是「AI 智能销售助理」，「助理」是核心定位，不是冷冰冰的系统。

## 二、AI 智能性设计

### 2.1 感知层：AI 持续在「看」什么

AI 不是等指令的工具，而是持续感知以下信号的工作伙伴：

| 信号源 | AI 从中读出什么 | 例子 |
|--------|----------------|------|
| 跟进原文（已解析） | 时间承诺、情绪变化、新痛点、决策人动态 | 「张总说周四前给答复」→ 生成约定提醒 |
| 客户档案 | 意向分变化、阶段停留时长、信息缺口 | 阶段停留超历史均值 150% → 建议诊断卡点 |
| 日历/约定 | 今天有约未执行、约后未补录 | 约了今天拜访但无跟进记录 → 傍晚提醒补录 |
| 知识库 | 某痛点有无成熟打法 | 命中 <40% → 备好给主管的求助件 |
| 行为数据 | 销售自己的使用习惯 | 连续忽略同类建议 3 次 → 自动降敏 |

### 2.2 自动化分级：AI 能「自动做」到什么程度

调研（Agentic CRM 共识）：**高频低风险的事自动做 + 事后告知；涉判断/涉对外的事人来拍板。** 分四级：

| 级别 | 名称 | 定义 | 本产品实例 |
|------|------|------|-----------|
| **L0** | 自动执行 · 无需告知 | 纯内部计算，随时可重算 | 意向分重算、待办列表刷新、知识库匹配度计算 |
| **L1** | 自动执行 · 事后告知 | 可逆的内部事务，AI 做完汇报 | 跟进原文的预解析草稿、给主管求助件的预整理、每日晨报生成 |
| **L2** | 备好草案 · 一键执行 | AI 把动作做到「只差一步」，那一步由人点 | AI 建议待办（采纳/改期/忽略）、话术草稿、策略草案 |
| **L3** | 必须人做 · AI 不碰 | 涉责任、涉对外、涉客户关系 | 档案写入确认、任何对外发送、成单确认 |

> 这就是「智能性」与「黄金法则」的统一：**不是「AI 什么都不许做」，而是「AI 把 L0–L2 全做掉，L3 留给人」**。V12 的偏差是把 L1/L2 也推给了人（一切从零开始），显得 AI 很笨。

### 2.3 智能待办引擎（重写 V12 的错误规则）

**准入门槛**（沿用 V2.2 §4.4）：客户已有 ≥1 条跟进记录 且 ≥1 条已确认痛点/需求——新线索不催生 AI 待办。

| # | 规则 | 生成的待办 | 级别 | 为什么合理 |
|---|------|-----------|------|-----------|
| R1 | 跟进中出现**明确时间承诺** | 「周四前：给张总发 POC 方案」 | 🔴 | 对客户的承诺，失信=丢单 |
| R2 | **约定跟进日到期未执行** | 「约了今天拜访李总，还没动静」 | 🔴 | 用户点名：这才是该催的 |
| R3 | 情绪强烈负面（关键词≥2 次） | 「48h 内安抚：王主任（烂尾怨气）」 | 🔴 | 情绪有保鲜期 |
| R4 | **高意向（≥75）** 且 >3 天未跟进 且最后一条未说明原因 | 「张总 81 分，上次聊到报价就断了」 | 🟡 | 用户点名：**高意向是前提**，低意向不催 |
| R5 | 阶段停留 > 该阶段历史均值 150% | 「诊断：赵敏在『临门一脚』停了 12 天」 | 🟡 | 停滞本身即风险 |
| R6 | 约后 24h 未补录跟进 | 「昨天的拜访还没沉淀要点」 | 🟡 | 记忆会衰减，只提醒不代录 |

**明确废除的 V12 规则**：
- ❌ 「X 天未跟进」（无意向前提的机械天数）→ 由 R4（高意向前提）+ R2（约定前提）替代；
- ❌ 「高意向客户：今天先演练再沟通」→ 演练是**工具**不是**义务**，改为中栏助理的软性建议（见 3.2），且仅当出现「新痛点从未演练过」时提一次。

**治理**（沿用 V2.2）：🤖 AI 建议徽章；[采纳] [改期] [忽略] 三键；同类连续忽略 3 次自动降敏；同客户同日最多一条催录。

### 2.4 待办卡片 = 行动单元（解决「点击后信息不够」）

传统设计：待办是一行字，点进去才开始找信息。
V3 设计：**卡片本身携带完成动作所需的一切**——为什么、上下文、一键动作。

```
┌──────────────────────────────────────────────┐
│ 🔴 周四前 · 给张总发 POC 方案        🤖 AI    │
│ 恒瑞汽配 · 张立群 · 意向 81 · 临门一脚        │
│ ────────────────────────────────────────     │
│ 依据：08-26 电话「你周四前把方案发我看看」      │
│ 缺什么：POC 方案还没生成                       │
│ ────────────────────────────────────────     │
│ [✨ 帮我起草方案] [📞 去跟进] [改期] [忽略]    │
└──────────────────────────────────────────────┘
```

- 点「帮我起草方案」→ AI 基于档案生成草案（L2），销售改完复制走（L3 对外发送归人）；
- 点「去跟进」→ 进客户详情并**自动定位到相关区块**；
- 采纳后进「我的待办」，忽略 3 次同类降敏。

## 三、AI 温度设计

### 3.1 助理人格

调研共识（情感化设计 / Agentic UX）：低风险场景用温暖对话语气，高风险场景用精确机械语气；适度拟人化，行为一致。

- **名字**：助理叫「**小智**」（界面固定称谓，建立人格锚点）；
- **形象**：中栏顶部固定头像区（🤖 圆形渐变头像 + 名字 + 今日状态一句话）；
- **语气分场景**：

| 场景 | 语气 | 示例 |
|------|------|------|
| 晨间问候 | 温暖、具体、不鸡汤 | 「早。今天有 2 个约定要兑现，张总那边周四的方案还没起草，我建议先弄这个。」 |
| 提醒催促 | 关心而非问责 | 「约了李总的拜访还没动静，是改期了吗？改期的话我帮你记上。」 |
| 任务完成 | 具体地高兴 | 「方案发出去了。这一步走完，张总这单就剩价格谈判了。」 |
| 成单庆祝 | 放大喜悦 | 「🎉 成了！恒瑞这单跟了 23 天，要不要我把过程沉淀成案例？下次同类客户直接复用。」 |
| 客户丢失风险 | 并肩作战 | 「王主任那边情绪不太好，我整理了 3 个安抚角度，要不要看看？」 |
| 低置信/不确定 | 诚实 | 「这个我没把握（知识库只命中 34%），我帮你整理好了，问下主管更稳。」 |
| 档案写入/对外动作 | 精确机械 | 「即将写入 3 条需求、1 条阻力。确认后不可自动撤销。」 |

### 3.2 中栏：小智的一天（「在场感」的内容编排）

中栏不是静态面板，而是**随时间和上下文变化**的助理存在。调研（NN/g）：常驻面板会被无视，**内容必须常换常新、与当下情境相关**。

| 时段/情境 | 中栏内容 |
|----------|---------|
| 早上首次打开 | 问候 + **今日晨报**：今天的约定、该兑现的承诺、一个值得推进的机会 |
| 白天常态 | **小智发现**（≤3 条，每条带依据 + 一键操作）：「赵敏的痛点『上线时间紧』你还没演练过，要不要先过一遍？（仅此类情况才提演练）」 |
| 有未解析跟进 | 置顶黄条：「你有 1 段跟进还没整理，2 分钟就能入档 →」 |
| 刚完成动作 | 即时反馈条：「已入档 3 条 ✔ 张总的意向分涨到 84 了」 |
| 傍晚 | 收尾：「今天跟进了 3 位客户。王主任那边明天记得安抚一下，我放在明天晨报里了。」 |

底部固定双 CTA：「💬 问小智」＋「🎙 录入跟进」。

### 3.3 微文案规范（冷 vs 暖对照）

| 场景 | ❌ 冷（系统腔） | ✅ 暖（助理腔） |
|------|---------------|----------------|
| 待办为空 | 「暂无待办事项」 | 「今天的事都清完了， nice。要不要趁热把赵敏那单推进一步？」 |
| 解析完成 | 「解析成功，请确认」 | 「我从这段话里找到了 4 条值得入档的，你过目。」 |
| 知识库未命中 | 「匹配度不足，无法生成」 | 「这个话题我知识储备不够，不瞎编。给主管的求助件我写好了，你发一下？」 |
| 加载中 | 「加载中…」 | 「我在翻张总这 23 天的跟进记录，马上好。」 |

### 3.4 背景工作状态（Living Breadcrumb）

AI 在后台做事时（预解析、起草方案），界面边缘有呼吸感的状态条：「小智正在读跟进记录… → 正在起草…」，不打扰但可见。完成后轻轻提示，可点开看成果。

## 四、三栏信息架构（恢复 V2.2 + 升级）

```
┌────────────────────────────────────────────────────────────────────┐
│ ⚡ AI 销售助理                                    🔔2  🔍 搜索客户… │
├──────────────┬──────────────────────────────┬──────────────────────┤
│ 左栏 · 今日   │ 中栏 · 小智（AI 助理）        │ 右栏 · 我的数据       │
│ （事务控制台）│ （温暖、在场、主动）           │ （仪表盘 · 可收起）   │
│              │                              │                      │
│ 🔴 承诺与约定 │ ┌──────────────────────┐    │ 月目标 ▓▓▓▓░░ 68%    │
│  卡片=行动单元│ │ 🤖 小智               │    │ 部门排名 3/12        │
│  （§2.4 样式）│ │ 早。今天有2个约定要兑 │    │ 本周跟进趋势 ～╲╱    │
│              │ │ 现，张总的方案建议先  │    │ 意向分布 ▟▛▄▂        │
│ 🟡 风险与提醒 │ │ 弄。                  │    │ 战报 Tab             │
│  卡片=行动单元│ └──────────────────────┘    │                      │
│              │                              │                      │
│ 👥 客户池     │ 💡 小智发现（≤3条，各带      │                      │
│  🔍搜索·筛选·│    依据+一键操作）            │                      │
│  排序·红黄绿  │                              │                      │
│  状态条       │ [💬 问小智]  [🎙 录入跟进]   │                      │
└──────────────┴──────────────────────────────┴──────────────────────┘
                    右下角：🎙 紫色 FAB
```

**三栏边界**（沿用 V2.2 §2.4）：左栏纯事实（冷静直接）/ 中栏纯帮助（温暖支持）/ 右栏纯数据（客观激励）。同屏一眼 = 要做的事 + AI 的帮助 + 我的成绩，这就是用户说的「三个层次」。

**客户池**（左栏底部，恢复 V2.2 §3.1）：
- 🔍 搜索框：实时过滤（姓名/公司/标签）；
- 筛选：阶段 / 意向档（🔥高 🌡中 ❄低）/ 状态色；
- 排序：意向分 / 最近跟进 / 阶段；
- 每行红黄绿左侧色条 = 状态；客户总量徽标「共 23 位」说明 4 个只是排序头部。

## 五、核心操作路径（每条路径画出「点完看到什么」）

### 路径 1 · 助理驱动的一天（主链路）
```
晨间打开 → 中栏小智晨报（今日约定+该兑现的承诺+一个机会）
   ↓ 点晨报里的「张总方案还没起草 →」
左栏对应待办卡高亮（依据/缺什么/一键动作同屏可见）
   ↓ 点「✨ 帮我起草方案」
小智后台起草（Living Breadcrumb）→ 草案就绪通知
   ↓ 点开草案 → 修改 → 复制 → 去微信发出（对外归人）
卡片变为「已发出，等周四反馈」→ 自动挂到张总时间线
```

### 路径 2 · 约定提醒 → 补录
```
🔴「约了今天拜访李总，还没动静」
   ↓ 拜访完回来，点卡片「🎙 补录跟进」
录入模态自动预填客户=李总、来源=今日拜访
   ↓ 贴内容 → 解析 → 勾选确认
档案更新 → 卡片自动勾销 → 中栏即时反馈条
```

### 路径 3 · 搜索任意客户
```
顶栏或客户池搜索框输「康泰」→ 实时过滤 → 点赵敏
   ↓
客户详情（档案 2/3 + 时间线 1/3 sticky）
   ↓ 点头像旁意向分 88
右侧滑出五维依据面板
```

### 路径 4 · 策略 → 话术 → 预演（保留 V2.2 黄金链路，不改）
确认过的素材有蓝点 → 「🔄 生成 AI 策略」→ 洞察（原话引证）→ 证据（KB 命中/<40% 走主管复制件）→ 策略卡 1/2/3（卡内生成话术）→ 底部统一预演卡 → 5 轮随机抽题 → 报告（痛点×轮次矩阵）→ 跳回最弱策略卡。

### 路径 5 · 问小智（自由问答）
```
中栏「💬 问小智」→ 对话抽屉
「王主任上次说的烂尾是怎么回事？」
→ 小智引用时间线原文回答 + 附「查看完整跟进」链接
```

## 六、待办规则修订对照表（直接回应点名问题）

| V12 规则 | 问题 | V3 规则 |
|---------|------|--------|
| 「张立群已 3 天未跟进」 | 无意向前提，低意向客户不跟进是正常的 | R4：**意向 ≥75** 且 >3 天未跟进且中断未说明原因，才提醒；并写明中断点 |
| —（无） | 约定到期没人管 | R2：**约定跟进日到期未执行** 🔴（用户点名的场景） |
| 「高意向客户：今天先演练再沟通」 | 把工具当义务；把握度高时是打扰 | 删除。演练只作为中栏软性建议，且仅当「**该客户存在从未演练过的新痛点**」时出现一次 |
| KPI 卡「待办 5」点击滚动 | 数字先行，低效 | 待办卡片**直接平铺在左栏**，无数字中转层 |

## 七、界面语言规范

- 助理自称「小智」，称用户「你」；
- 禁止系统腔：「操作成功」「暂无数据」「请稍后」→ 见 §3.3 对照表；
- 禁止 PM 腔（沿用 V12 成果）：界面不出现「黄金法则 / Human-in-the-loop / D1-D5 / 战术参谋」；
- AI 产出物统一视觉：虚线框 + 🤖；确认后实线——规则不靠标语，靠交互本身。
