## 一、设计说明（非功能，供面试讲解）
### Q1：客户已有 CRM，为何还选你？
CRM 用户普遍不愿录入——填信息麻烦，录入与赢单无直接关联；CRM 功能重，手机打开不便。
| 维度 | 传统 CRM | AI 销售助理 |
|------|----------|-------------|
| 信息录入 | 手动填写费时费力 | 语音/粘贴 → AI 解析 → **销售确认后**回写档案 |
| 与赢单关系 | 只记录不赢单 | 心理洞察 + 证据检索 + 策略话术 + 意向量化，直接服务赢单 |
| 移动端 | 重、慢 | 响应式单页，触控友好 |
| 智能程度 | 只有数据无洞察 | 痛点本质拆解、同类案例推荐、风险预警、意向评分 |
### Q2：线下录音涉及隐私，如何处理？
严格依据《个人信息保护法》《数据安全法》：录音仅用于沟通结构化分析；加密存储，仅本人及授权管理者访问；沟通前知情同意提示；默认留存 90 天到期清除；支持随时撤回授权。
### Q3（V2.2 补充）：为什么坚持"AI 只建议、人必确认、人负责对外"？
1. **责任归属**：档案是公司资产，写入要有人担责；
2. **信任建立**：亲自确认过的数据销售才敢用；
3. **噪声防火墙**：销售判断力有限，AI 直写等于放大幻觉风险；
4. **渠道尊重**：像"向主管求助"这类对外动作，本就发生在销售的日常人际网络里（微信一句"哥，帮我看看这个"远比系统消息有效），工具不该也不需要越过这道人际边界——所以设计成**一键复制、人来发送**；
5. **越用越准**：每一次勾选、编辑、备注都在反哺模型精度。
> 全文铁律：**AI 可以提醒、可以备稿，但不点击不生效；出了系统的动作，也归人发。**

## 二、总体架构与设计原则
### 2.1 核心原则
- **客户档案 = 作战室**：痛点管理、策略生成、跟进留痕、综合预演全在此发生；
- **工作台 = 指挥中心**：左栏事务 / 中栏 AI 帮助 / 右栏数据；
- **知识库 = 弹药库**：AI 检索的第一证据源，缺弹药时驱动"找主管 + 补库"而不是硬编答案；
- **触发黄金法则**：解析、策略、话术、预演、评级展开——每一个 AI 动作都有明确销售触点。
### 2.2 技术栈
| 项 | 选择 |
|----|------|
| 形态 | 纯静态多文件，原生 JS，无构建 |
| 文件 | `index.html` + `styles.css` + `app.js` + `mock-data.js` + `charts.js` |
| 依赖 | 零外部库、零 CDN、零网络请求（演示态） |
| 部署 | GitHub Pages，双击 `index.html` 离线可跑 |
| 主题 | 浅色主题 |
| 响应式 | 桌面三栏 + 手机单列堆叠 |
### 2.3 页面结构
```
┌──────────────────────────────────────────────────────────────┐

├───────────────┬────────────────────────┬─────────────────────┤

│               │ 💬AI对话 ＋ 🎙录入跟进     │                     │

                            右下角：🎙 紫色 FAB 浮动按钮（唤起跟进录入大模态）
```

### 2.4 三栏定位原则（不重叠）
| 区域 | 栏名称 | 角色 | 语气 | 内容边界 |
|------|--------|------|------|----------|
| 左栏 | 今日待办 | 事务控制台 | 冷静、直接 | 待办、客户、风险——纯事实 |
| 中栏 | AI 助理 | AI 小助理 | 温暖、支持 | 方法、知识、洞察、双 CTA——纯帮助 |
| 右栏 | 我的数据 | 数据仪表盘 | 客观、激励 | 业绩、排名、战报——纯数据 |

## 三、工作台三区详解
### 3.1 左栏：今日待办
- 早间提醒 + 风险预警 + 待办提醒合并；卡片含客户全称、紧急标签、预警标签、预警详情、可执行事项①②③、决策人与截止时间；
- V2.x 新增：**AI 自动提取的待办**入此栏，右上角浅蓝「🤖 AI 建议」徽章（详见 4.4）；
- 客户池：搜索实时过滤 + 组合筛选 + 自定义排序；卡片红黄绿色条区分状态。
### 3.2 中栏：AI 助理
- AI 问候（每日一次，温暖克制）；今日方法锦囊；知识库推荐（含💡推荐理由）；小助理发现（三条洞察各带一键操作）；
- 双 CTA 固定底部：「💬 AI 综合查询」＋「⚡ 动力加速」；
- 存在未解析跟进原文时，置顶黄底引导条："你有 N 条跟进内容尚未解析入库 → 点此录入"——只引导，不代做。
### 3.3 右栏：我的数据（可收起）
收起钮蓝色圆形 32px；模块含月目标进度、部门排名 SVG（自我高亮）、绩效档位、激励进度、战报 Tab（部门轮播 / 我的列表筛选排序）。

## 四、核心功能设计 ★ 本版重点 ★
### 4.1 跟进记录录入与 AI 解析（链路起点）
#### 4.1.1 三类信息来源
| 来源 | 操作方式 | 备注 |
|------|----------|------|
| 🎤 直接语音录入 | 点麦克风说话，实时转文字 | Web Speech API 优先，不可用降级文字 |
| 📄 录音转文字粘贴 | 外部工具转好后整段粘贴 | 最高频场景 |
| ⌨️ 手动文字输入 | 直接键入 | 兜底 |
#### 4.1.2 解析入口：居中大模态
- 尺寸宽 = min(900px, viewport−80px)，居中，半透明遮罩；
- 结构：标题栏｜≥240px 输入区（占位符引导）｜主按钮「🔍 开始解析」＋辅助排（🎤 / 📎 / 💾存草稿 / 🗑清空）；
- 主按钮禁用条件：文字 <20 字且语音 <15 秒；
- ESC / 点遮罩不关闭；草稿 localStorage 保存 24h。
#### 4.1.3 多点提醒销售录入（仅提醒，绝不代录）
| 触发位置 | 条件 | 表现 |
|----------|------|------|
| 工作台-今日待办 | 待办创建于过去 3 天内、约定拜访时间也在过去 3 天内、该客户无跟进记录 | 卡片右上「📝 待补录」黄标 |
| 客户档案最上方 | 最近拜访 >24h 未录跟进 | 横幅："上次沟通要点还没沉淀 → [立即录入]" |
| 工作台右栏 | 已建商机 48h 未录跟进数 >0 | 红点数字 |
| 顶栏通知中心 | 以上事件汇总 | 未读角标 |
去重：同一客户同一天最多催一次。
#### 4.1.4 解析确认弹窗（四大分组 + 直觉判断）
```
┌──────────────────────────────────────────────────┐
│ 🤖 AI 解析结果确认                                 │
│ 从跟进内容中提取到以下信息，请勾选确认：             │
├──────────────────────────────────────────────────┤
│ ☑ 全选 / 取消全选             已选 7 / 7          │
├──────────────────────────────────────────────────┤
│ 🎯 客户需求                                        │
│   ☑ 新增：需 API 对接现有 ERP 系统                 │
│      来源 [08-20 15:15 李华微信] [✏️][🗑]          │
├──────────────────────────────────────────────────┤
│ 😣 客户痛点                                        │
│   ☑ 升级：预算收紧（Q3 CFO 削减非核心 IT 支出）    │
│   ☑ 新增：技术团队顾虑 ERP 兼容性                  │
├──────────────────────────────────────────────────┤
│ ⚠️ 成交阻力                                        │
│   ☑ 确认细化：CFO→CEO 两级审批，单次上限 30 万      │
│   ☐ 低置信 ⚠：疑似内部意见分歧（置信度 62%）       │
├──────────────────────────────────────────────────┤
│ 😊 情绪判定（参考）                                │
│   ☑ 整体谨慎务实、成本极度敏感                     │
├──────────────────────────────────────────────────┤
│ 本次沟通后你的直觉判断（用于校准 AI，可不填）：      │
│ 程度：[很低 ○] [低 ○] [中 ●] [高 ○] [很高 ○]       │
│                                                     │
│ ✍️ 备注你的判断依据（选填，≤200 字）：              │
│ ┌───────────────────────────────────────────┐    │
│ │ 例：CFO 只是口头同意预审，还没走正式审批流；   │    │
│ │ 竞品那边据说也在压价……                    │    │
│ └───────────────────────────────────────────┘    │
│                                     78 / 200       │
├──────────────────────────────────────────────────┤
│ [✅ 确认更新档案] [📥 仅保存跟进记录] [❌ 不保存]    │
└──────────────────────────────────────────────────┘
```
**备注字段规格**：
- 可见性：**仅在销售选择了某个程度后才显示输入框**（未选则隐藏，减少视觉噪音）；
- 上限 200 字，右下角计数；
- 用途：① 存入本条跟进记录；② 作为 D5 维度的证据在评分面板展示；③ 作为语料供 AI 校准主观-客观偏差；
- 属于直觉判断整体的一部分——若销售点了"不保存"，备注一并丢弃；"仅保存"路径则随跟进原文留存但计入 D5 历史。
其余弹窗规则沿用：低置信(<75%)默认不勾选；每条可编辑可删除；客户基础信息变更走行内编辑留痕，不在解析分组内。
#### 4.1.5 三种处置方式（铁律条款）
| 按钮 | 行为 |
|------|------|
| ✅ 确认更新档案 | 勾选项分别写入需求/痛点/阻力/情绪对应模块；各模块右下角时间戳刷新；写入 changelog；跟进同步进生命周期时间轴；直觉判断（程度+备注）记入 D5 |
| 📥 仅保存跟进记录 | 整条原文进时间轴，**结构化字段不动**；策略区蓝点亮起；直觉判断仍记入 D5 历史（因为它是主观输入不是 AI 写入） |
| ❌ 不保存 | 全部丢弃，二次确认防误触 |
#### 4.1.6 更新时间戳与修改留痕
- 【客户基础信息】【需求】【痛点】【阻力】各模块卡片右下角灰色小字：`🕐 更新时间：2026-08-22 14:35`；hover 显示来源跟进与操作人；超 30 天未更变警示黄；
- 每次 confirm 写入 `{时间, 字段, 旧值, 新值, 来源跟进ID, 操作人}`；档案底部「📜 修改历史」支持 diff 与回滚。

### 4.2 客户档案 — AI 策略（手动触发的分段作战地图）
#### 4.2.1 触发原则
- **不存在任何自动生成时点**；进入档案、确认跟进均不算；
- 策略区常态是一张引导卡 + 大按钮「🔄 生成 AI 策略」（已有策略时变「🔄 重新分析」，旁注上次分析时间）；
- 有未消化素材（仅保存的跟进 / 新确认入档信息）时按钮亮蓝点提醒；
- 分析输入仅限两类已确权数据：已确认入档字段 + 已保存跟进原文。
#### 4.2.2 第一段：客户心理洞察（关心问题本质 1/2/3）
每条必须引用客户原话或具体跟进日期作证，无证据不列：
```
🧠 张总(CTO) 当前真实关切 · 心路历程
─────────────────────────────────────
1️⃣ 数据安全焦虑（表层诉求）
   ↳ 本质：担心私有化部署能力不足、ERP 兼容失败导致技术信任崩塌
   📎 原话：「你们接口要是把我们 ERP 搞挂了谁负责」（08-22 电话）
2️⃣ 预算审批两难（深层顾虑）
   ↳ 本质：无法向 CFO 解释 ROI 为何压到 Q4 才见效
   📎 行为证据：索要分期方案但回避总价话题（08-18 会议纪要）
3️⃣ 对竞品 B 的沉默观望（潜在风向）
   ↳ 本质：接触过但未表态，是在等更优解而非拒绝我们
   📎 信号：08-20 会议提及竞品时未反驳、笔记频次上升
```
排序按阻碍成交权重倒序，最多 3 条。
#### 4.2.3 第二段：突破解法 + 双通道证据检索
Hybrid Retrieval，先查内部知识库（RAG）：
```
【针对问题 1：数据安全焦虑】
✅ 内部打法（命中 ≥40%）：《制造业数据迁移零风险 SOP》
   💡 摘要：三步灰度迁移 + 回滚开关 + 第三方审计背书
   🔗 /kb/manufacturing/data-migration-sop   📄 附《零风险方案.pptx》
📚 同类客户案例：客户 A · 汽车零部件 · SAP 迁移 4 周 · 零事故上线
   🔗 /kb/case/A-auto-parts-migration
```
**知识库匹配不足 40% 时**——不用联网顶包，降级为人工升级指引：
```
🌐 外部线索补充（仅供参考，未经内部验证）：
   · Gartner 2026：73% 制造业 CTO 将私有化部署列为选型 Top3 → [链接]
┌────────────────────────────────────────────────────────┐
│ ⚠️ 内部知识库对该问题覆盖不足（匹配度 31%）。            │
│ 为避免误导客户或过度承诺，AI 不据此给出方案。            │
│ 👉 建议：把下面整理好的信息复制发给你的直属主管，         │
│    请其确认解决方案，并安排将该结论补录进知识库，         │
│    下次同类问题即可直接命中。                             │
│                                                          │
│ [📋 复制信息，发给主管]     [📚 稍后补录进知识库]         │
└────────────────────────────────────────────────────────┘
```
**为什么是"复制"而不是系统直发**：
1. 销售向主管求助天然发生在微信/飞书等私人沟通里，系统代发既不合群也无实际送达保障；
2. 发送这个动作本身就该过销售的手——这符合全文"对外传递由人执行"的一致原则；
3. 零集成成本，任何 IM 都通用。
**点击复制后写入剪贴板的标准文本模板**：
```
【AI 策略求助】
客户：北京中科智云信息技术有限公司（方案沟通中）
待解问题：数据迁移安全风险如何兜底？
客户原话证据：「你们接口要是把我们 ERP 搞挂了谁负责」（08-22 电话）
外部线索参考：
 · Gartner 2026 制造业 CRM 选型报告 → https://…
内部知识库现状：匹配度 31%，暂无成熟 SOP。
请求：请帮忙确认应对口径；确认后我会把结论补录进知识库。
—— 来自 AI 销售助理 · 2026-08-27 15:40
```
toast 提示："✅ 已复制，去你的沟通渠道粘贴发送即可"。联网调用仅在且仅在 <40% 分支出现，且其结果永不参与策略直接生成，只作为附件素材流转。
#### 4.2.4 第三段：策略 1/2/3（先有策略，才有话术）

```
┌─ 策略 1 · 针对【数据安全焦虑】────────────────┐
```

#### 4.2.5 第四段：按策略生成参考话术

### 4.3 AI 客户意向综合评分（五维加权）
#### 4.3.1 维度与权重
权重从过往成功经验回归得出，初始取行业基准，上线后按本司赢单样本每周校准。
| 维度 | 权重 | 打分依据 |
|------|------|----------|
| D1 有无预算 | 25% | 跟进中金额/审批信号/预算压缩信号 |
| **D2 业务痛难点获取** | 25% | **销售已获取到的具体业务痛难点的数量与深度**——不区分来源姿态：客户主动陈述、或销售提问后客户回答，均可计入；判分核心看信息的具体度（是否落到业务环节、有量化影响、明确涉及角色） |
| D3 痛点×产品匹配度 | 20% | 已获取痛难点 ↔ 产品能力的映射相似度 |
| D4 关键决策人支持度 | 20% | DMU 各角色立场词、见面频率、推进承诺 |
| D5 销售主观判断 | 10% | 每次解析弹窗采集的程度（很低~很高→0/25/50/75/95）**＋ 其文字备注作为佐证材料一并留存展示** |
总分 = Σ(Di×Wi)，四舍五入。
> D2 口径说明（对应反馈④）：该维度衡量的是**信息获取成果的质量**，而非客户的表达主动性。销售通过提问深挖出的痛难点与客户自己倒出来的同样有价值——甚至前者体现了更强的控场能力。因此评据为"档案+跟进中沉淀的具体痛难点条目及其颗粒度"，并在证据行标注来源属性（主动陈述 / 问出）。
#### 4.3.2 分层展示
| 区间 | 等级 | 颜色 | 联动 |
|------|------|------|------|
| ≥80 | 🔥 高 | 红 | 左栏置顶 |
| 60–79 | 🌡 中 | 黄 | 正常节奏 |
| 30–59 | ❄ 低 | 蓝 | 建议培育 |
| <30 | ⚪ 未激活 | 灰 | 公海候选 |
| 缺失≥2 维 | ⚠ 证据不足 | 紫灰 | 先补关键跟进 |
#### 4.3.3 交互与边界
- 档案头部评分数字可点击 → 右滑出依据面板：五根进度条 + 每维逐条证据 + 趋势箭头 + 单条提升建议；
- D2 证据行示例（体现新口径）：
```
D2 业务痛难点获取  ██████████░░░░ 76%
   ✓ 已获取 3 个具体痛难点：
     · ERP 接口老旧担忧（销售追问获知 · 08-20 李华）
     · 分销商对账效率损失（客户主动陈述 · 08-18 会议）
     · 多部门数据孤岛撞单（销售追问获知 · 08-22 张总）
   ⚠ 各痛点的量化影响金额尚未确认 → 补齐可 +10 分
D5 最近主观判断：中偏高（08-22）
   ✍️ 你的备注：「CFO 口头同意预审，没走正式流程，还差一步」
```
- 边界声明：评分为派生展示指标，基于已确权数据联动重算，不回写字段、不需确认；D5 因依赖销售输入全程透明展示以防黑箱感。

### 4.4 AI 自动提取待办
**准入门槛**：客户已有 ≥1 条跟进记录 且 已有 ≥1 条已确认痛点/需求。
| # | 规则 | 生成的待办 | 级别 |
|---|------|-----------|------|
| R1 | 跟进中出现明确时间承诺 | 「{日期}前：{承诺事项}」 | 🔴 |
| R2 | 情绪强烈负面（愤怒/受挫关键词≥2 次） | 「48h 内安抚跟进：{客户}({诱因})」 | 🔴 |

## 七、沟通预演 ★ V2.2 整章重构 ★
### 7.1 设计理念转变
| | 旧思路（每策略一场） | 新思路（模块统一一场） |
|--|--|--|
| 模拟对象 | 单一异议场景下的角色扮演 | **接近真实客户的综合对手盘** |
| 考察目标 | 单点话术熟练度 | 对**整套策略体系的理解深度与临场调度**——客户不会告诉你在考你哪一页 |
| 出题方式 | 固定剧本 | **随机抽题**：每次进入题目组合与顺序都不同 |
| 结果形态 | 单场景评分 | 总分 + 四维能力 + **痛点×轮次覆盖矩阵** |
### 7.2 流程
```
[策略模块底部] [▶ 开始综合预演]
        ↓
准备页：显示本轮将覆盖的痛点数 / 轮次 / AI 建议的人设
        人设建议 = 强阻力对应角色（如 CTO 张总 · 技术严谨 + 成本敏感）
        可选项：☑ 允许查阅策略小抄（使用会如实计入报告）
        ↓
实战对话：AI 按"抽题引擎"出招，销售录音/打字回应
        ↓
任意时刻 [结束演练]
        ↓
评估报告（见 7.5）
```
### 7.3 抽题引擎（本功能的技术灵魂）
**题库构建时机**：每次点「🔄 生成 AI 策略」时，分析结果除了产出洞察/证据/策略之外，**同时为每个痛点本质生成 2–3 道候选考题**并入库，形如：
| 痛点本质 | 层次 | 候选题（AI 以人设口吻发出） |
|----------|------|---------------------------|
| 问题 1 数据安全焦虑 | 表层 | "你们说私有化，但我担心你们驻场实施会把我们 ERP 弄出毛病来。" |
| | 追问 | "回滚方案我听过很多家都这么讲，真出事的时候你们多久能恢复？赔吗？" |
| | 压力 | "隔壁 B 家说他们兜底赔付直接写合同里，你怎么接？" |
| 问题 2 预算两难 | 表层 | "80 万我签不了，这数字我根本过不了财务那关。" |
| | 追问 | "那你告诉我，凭什么 Q4 见效？我要怎么跟 CFO 讲？" |
| 问题 3 竞品观望 | 压力 | "实话说我也在看别家，他们便宜 15%，你们给我个理由。" |
**运行时抽题规则**：
1. 单场默认 5 轮（可随痛点数自适应：N 个痛点 ≈ N+2 轮）；
2. **覆盖约束：每个痛点至少被抽中 1 次**——这是 V2.2 明确要求的考核底线，保证"综合掌握"必须落实到每一个识别出的关切点；
3. 其余轮次随机补位，优先抽更高难度层次（表层→追问→压力）实现陡度递进；
4. 同场不重复同一题；
5. 题目以人设口吻自然抛出，不给任何"现在是第几考点"的提示——制造真实感。
### 7.4 策略小抄（可选辅助）
- 准备页可勾选启用；启用后对话视图右侧提供可折叠面板展示 3 张策略卡要点与已生成话术；
- 面板每次展开使用会被计数；
- 报告如实呈现："本场你查阅小抄 2 次"——**不自欺的练习才有价值**，用没用、用了几次，销售自己心知肚明。
### 7.5 评估报告
| 模块 | 内容 |
|------|------|
| 总分 + 四维分 | ①倾听与识别 ②策略匹配度 ③表达与专业度 ④推进与促单 |
| 痛点×轮次矩阵 | 3 行（痛点）× N 列（轮次）热力格：该轮是否考此痛点 / 回答质量好/中/差 / 未被考到灰格 |
| 覆盖率徽标 | "3/3 痛点均已应答 · 其中 1 个回答未扣准策略要点" |
| 逐轮点评 | 每轮：客户问题 + 你的原话片段 + ✓亮点 / △不足 + 优化后的示范答句 |
| 小抄使用次数 | 如实数字 |
| 总结建议 | 指向最弱痛点对应的策略卡与知识库补读链接 |
旧的按场景评分维度并入四维体系，不再各自独立。
### 7.6 与其他功能的衔接
- 从预演报告的"未扣准要点"可直接跳回对应策略卡修正理解，然后 [再来一场]；
- 预演表现可作为面试演示的压轴故事线（演练 4）。

## 十二、错误处理
| 场景 | 处理 |
|------|------|
| 语音 API 失败 | 降级文字，toast 提示 |
| 解析无结果 | 弹窗提示可补充关键词或手动添加 |
| 知识库检索异常 | 等同 <40% 路径：不出方案，走复制升级 |

## 十五、核心操作链路（六条演练）
**演练 1 · 查看档案全貌**：左栏点客户 → 全页面 → 点头部评分展开五维依据（注意 D2 证据行的来源标注与 D5 备注原文）→ 基础信息看右下时间戳 → 时间轴切 Tab。
**演练 2 · 跟进录入→解析→确认闭环**：「＋ 新增跟进记录」→ 居中大模态贴/说内容 → 「🔍 开始解析」→ 四分组勾选（取消一项低置信试试）→ 选程度"中偏高" → **填一行备注"竞品在压价， CFO 还没正式批"** → 点「✅ 确认更新档案」→ toast 汇报 → 时间戳变化、时间轴穿插、历史留痕、再到评分面板验证备注已挂上。
**演练 3 · 仅保存路径**：再来一条 → 解析 → 这波点「📥 仅保存」→ 验证字段纹丝不动、时间轴+1、蓝点亮，同时 D5 历史多了一条（备注随之留档）。
**演练 4 · 策略全流程 + 统一综合预演（压轴）**：
1. 点「🔄 生成 AI 策略」→ 洞察三条看原话引证 → 证据区看 KB 命中；
2. 构造一次 <40% 演示 → 看「📋 复制信息发给主管」→ 实际粘贴出来核对四要素；
3. 分别点三张卡的「💬 生成参考话术」，把策略 1 的改一版；
4. 点底部唯一「▶ 开始综合预演」→ 准备页勾选"允许小抄" → 5 轮对话（你会感到客户在不同痛点间跳跃）→ 故意在某一轮回不上来；
5. 结束 → 报告查看：总分四维、**痛点×轮次矩阵精确指出你刚才失手的那个痛点**、小抄用了几次、逐轮示范句。
**演练 5 · 成单检测 → 案例沉淀**：模拟成单 → 确认总结 → 战报/数据/待办三处联动 → 案例入知识库。
**演练 6 · 手机端**：<768px 单列 → 悬浮球长按语音 → 全屏模态 → 解析确认 → 预演气泡流+抽屉小抄 → 底部返回。
